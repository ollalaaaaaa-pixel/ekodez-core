# Default-deny для Telegram

## Назначение

Роль определяется только числовыми allowlist-ID из конфигурации. Любой неизвестный отправитель не получает команды мастера или владельца и попадает только в клиентский сценарий.

## Ранбук

1. Считай `OWNER_TG_ID` и `ALEXEY_TG_ID` числовыми значениями; не угадывай роль по имени, username или тексту сообщения.
2. Сначала классифицируй отправителя: владелец, мастер, клиентский сценарий. При отсутствии настройки роли возвращай ту же общую ошибку отказа.
3. Применяй default-deny к каждой команде и callback, включая deep-link и повторную доставку.
4. В клиентском сценарии собирай только согласованный минимум и соблюдай rate-limit; отмена должна работать даже после превышения лимита.
5. Алерты владельцу содержат статус и безопасный объектный контекст, без телефона, ИНН, банковских реквизитов и адреса.
6. Имя бота и ссылки берутся только из `BOT_USERNAME`/конфига; не зашивай username в код.

## Чек-лист

- чужой TG-ID не получает мастерские/владелческие команды;
- unknown и ненастроенная роль отказаны одинаково;
- rate-limit проверен тестом;
- клиентский сценарий отделён от legacy ingest;
- алерт не содержит PII;
- bot username конфигурационный.

## Типичные ошибки проекта

- доверять username вместо числового TG-ID;
- пропустить защиту callback-кнопки;
- отправить телефон в сводном сообщении;
- позволить rate-limit блокировать cancel;
- считать любое сообщение клиента мастерской командой.
