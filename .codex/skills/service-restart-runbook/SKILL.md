# Ранбук рестарта сервисов

## Назначение

Перезапуск должен убрать старые процессы, запустить именно запланированные задачи и доказать, что wrapper действительно стартовал.

## Ранбук

1. Сними статус задач `EkodezBackend` и `EkodezFrontend`, текущие PID на портах 8000 и 5173 и последние строки логов.
2. Останови задачи `schtasks /End` или штатным способом. `Stop-ScheduledTask` останавливает задачу, но не гарантирует завершение дочерних процессов.
3. Для каждого PID на 8000/5173 проверь командную строку и владельца. Заверши только подтверждённые процессы; неизвестный PID сначала расследуй.
4. Запусти задачи штатной командой. Не запускай второй dev-сервер вручную поверх scheduled task.
5. В логах найди свежую строку `WRAPPER START` и время старта. Без неё запуск не считай подтверждённым.
6. Проверь `GET /health`, `GET /health/db` и HTTP 200 фронтенда на `http://127.0.0.1:5173`. В отчёте укажи PID, время и ответы.

## Чек-лист

- задачи остановлены и запущены;
- старые проверенные PID завершены;
- `WRAPPER START` есть в новых логах;
- backend health и health/db отвечают `ok`;
- frontend отвечает 200;
- рабочая БД не мигрировалась во время рестарта.

## Типичные ошибки проекта

- считать `Stop-ScheduledTask` завершением дочернего uvicorn/node;
- убить PID без проверки порта и командной строки;
- принять старую строку лога за новый старт;
- проверять только главную страницу и пропускать `/health/db`;
- оставить второй ручной сервер на занятом порту.
