# Регламент read-only ревью

## Назначение

Ревью доказывает факты командами и заканчивается `READY` либо списком расхождений. Диагностические тесты не должны писать в рабочую БД.

## Ранбук

1. Зафиксируй HEAD, ветку, remote SHA и `git status --short`. Не выполняй pull, merge, commit, migration или сервисный restart.
2. Проверь diff и untracked по запрещённым путям: `*.db`, `*.xlsx`, `.env`, ключи, токены, вложения и секреты. Отдельно проверь бинарники вне `docs/marketing` и ассетов сайта.
3. Проверь Alembic current/heads и потребуй одну голову; две головы — расхождение.
4. Найди имена ключевых тестов и запусти только безопасные проверки с тестовой БД.
5. Проверь, что health-запросы не меняют состояние, а рабочие процессы и БД не трогались.
6. Отчёт строй как «Статус / Подтверждённые факты со ссылкой на вывод / Риски / UNRESOLVED». Неподтверждённое не называй фактом.

## Чек-лист

- запрещённых файлов в diff нет;
- секреты и открытые реквизиты не выведены;
- одна Alembic head;
- тесты названы точно;
- прод не изменён;
- вердикт `READY` или список расхождений.

## Типичные ошибки проекта

- считать чистый `git status` доказательством чистой БД;
- читать и печатать `.env` в отчёт;
- запускать миграцию «только для проверки»;
- пропускать бинарные вложения;
- выдавать заявление из чата без вывода команды за подтверждённый факт.
