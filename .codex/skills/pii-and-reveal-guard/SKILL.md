# PII и раскрытие данных

## Назначение

Полные персональные и платёжные данные находятся только в шифрованном хранилище. По умолчанию API, UI, логи и алерты показывают маскированное значение.

## Ранбук

1. Раздели данные по ролям: мастер видит контакты заявки и адрес объекта; реквизиты плательщика доступны только владельцу.
2. Храни телефон, имя, адрес и реквизиты в `encrypted_pii` с Fernet-ключом из конфигурации. Не выводи ключ, токен или полный ИНН.
3. Для reveal требуй localhost (`request.client.host` 127.0.0.1/::1) либо аутентифицированную сессию владельца по утверждённому сценарию.
4. Reveal с не-localhost без HTTPS должен возвращать HTTP 426 Upgrade Required с подсказкой. Остальные LAN API могут работать по HTTP с сессией и маскировкой.
5. Cookie использует HttpOnly и SameSite=Strict; Secure включается конфигурацией вместе с HTTPS.
6. Любой challenge записывает `challenge_issued` без кода и TG-ID. Ненастроенная роль падает в общей ошибке отказа.
7. Закрытые лиды очищаются через 12 месяцев: удаляется `encrypted_pii` и связанные временные секреты, остаются обезличенные служебные поля, статус, даты и аудит без PII.

## Чек-лист

- маскирование проверено в API, UI, логах и Telegram;
- reveal защищён localhost/сессией и 426 без HTTPS;
- proxy-заголовки не подменяют `request.client.host`;
- audit не содержит код, TG-ID и реквизиты;
- retention-тест подтверждает удаление только разрешённых полей.

## Типичные ошибки проекта

- доверять `X-Forwarded-For` для localhost-проверки;
- вернуть полный телефон в Telegram-алерте;
- логировать код challenge или ИНН;
- считать отсутствие PII-ключа поводом показать plaintext;
- удалять весь лид вместо одного `encrypted_pii` после retention.
