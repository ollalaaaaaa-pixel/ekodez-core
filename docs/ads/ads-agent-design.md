# CORE-ADS-AGENT — дизайн контура рекламной аналитики

Дата: 14.09.2026

## Цель

Локально импортировать выгрузки Яндекс Директа, Яндекс Бизнеса и 2GIS, связывать рекламные контакты с лидами без хранения открытых телефонов, рассчитывать CPL/ROMI и раз в неделю готовить безопасный дайджест и черновики решений. Система не отправляет письма и не меняет рекламные кабинеты.

## Границы

- Фаза 1 работает только с локальными XLSX, CSV и HTML-таблицами с расширением XLS из `C:\D\Экодез\ads\<platform>\`.
- OAuth и Яндекс Direct API относятся к фазе 2 и не реализуются.
- Все административные endpoints, экран «Реклама», очередь атрибуции, импорт, журнал и рекламные уведомления доступны только роли `owner`.
- Рабочая БД, сервисы и `main` не изменяются до отдельной команды «применяй».
- В Telegram, UI, журналах, уведомлениях и Markdown-отчётах нет открытых телефонов или иных PII.

## Хранение

### `ad_spend`

- `id` INTEGER PK;
- `platform` VARCHAR(30), допустимы `yandex_direct`, `yandex_business`, `2gis`;
- `campaign` VARCHAR(200);
- `period_start`, `period_end` DATE;
- `spend` NUMERIC(14,2);
- `impressions`, `clicks`, `conversions` INTEGER;
- `created_at`, `updated_at` DATETIME;
- уникальность: `(platform, campaign, period_start, period_end)`.

### `ad_call_log`

- `id` INTEGER PK;
- `platform` VARCHAR(30);
- `call_date` DATE;
- `phone_hash` CHAR(64);
- `source_file` VARCHAR(255);
- `created_at` DATETIME;
- уникальность: `(platform, call_date, phone_hash, source_file)`.

`phone_hash` — HMAC-SHA256 от канонических 11 цифр телефона. Ключ выводится из `PII_FERNET_KEY` доменно-разделённым HMAC с меткой `ekodez-ad-phone-v1`. Голый SHA-256 запрещён. Хеши бессрочны; plaintext не сохраняется ни в одной таблице.

### `ad_import_runs`

Хранит платформу, basename файла, SHA-256 файла, статус `ok/error`, количество импортированных и обновлённых строк, начало/конец периода, безопасную причину ошибки и время запуска. Полный путь и содержимое строк не сохраняются.

### `notifications`

Поля: `id`, `kind`, `payload` JSON, `created_at`, `read_at`. Виды: `ads_import_ok`, `ads_import_error`, `ads_upload_reminder`, `ads_alert`, `draft_ready`. Payload проходит allowlist-сериализацию и не принимает телефон, адрес, ИНН, реквизиты или токены.

### `leads`

Добавляются nullable-поля `utm_source`, `utm_campaign`, `attributed_platform`, `attribution_method`, `attributed_at`. Метод допускает `utm`, `phone_match`, `manual`. Для решения «не реклама» используется `attributed_platform = NULL`, `attribution_method = manual`.

## Локальная конфигурация

В репозитории находится только `docs/ads-config.example.json`. Рабочий файл — `C:\D\Экодез\ads\config.json`, вне Git. Для каждой площадки задаются `manual_import`, `reminder_period_days`, `target_cpl` и `zero_lead_spend_threshold`. По умолчанию `reminder_period_days = 7`; денежные цели без значения остаются `null` и не генерируют соответствующий алерт.

## Импорт

Адаптер выбирается по платформе и распознанным заголовкам. Поддерживаются XLSX, CSV и HTML/XLS. Нормализация заголовков: trim, lower, `ё→е`, схлопывание пробелов. Денежные значения читаются только через `Decimal`.

Импорт одного файла выполняется в транзакции. `ad_spend` обновляется по составному ключу. Звонки дедуплицируются уникальным индексом. Успех или безопасная ошибка создают запись `ad_import_runs` и уведомление. Ошибка файла не оставляет частично импортированные рекламные строки.

## Атрибуция

1. Если есть UTM, платформа определяется по словарю aliases и записывается методом `utm`.
2. Для лида без UTM и без manual-решения полные PII расшифровываются только в памяти, телефон нормализуется и превращается в HMAC. Ищутся звонки в окне ±7 календарных дней от `order_at/created_at`.
3. Единственная площадка даёт `phone_match`; отсутствие или несколько площадок оставляет лид в очереди.
4. `manual` не перезаписывается автоматикой.

## Метрики

- CPL = расход / число атрибутированных лидов; при нуле лидов — `null` с причиной.
- ROMI = `(фактическая выручка − расход) / расход × 100%`.
- Выручка берётся только из `transactions.kind = income`, связанных через `lead_id`.
- Абонентский клиент учитывается по фактическим платежам соответствующего месяца; `ContractPeriod.price_snapshot` не прибавляется повторно.
- Все деньги сериализуются строкой с двумя знаками.

## API и роли

Router `/api/ads` вызывает `require_owner(request)` на каждом endpoint:

- `POST /api/ads/import`;
- `GET /api/ads/metrics`;
- `GET /api/ads/import-runs`;
- `GET /api/ads/attribution-queue`;
- `POST /api/ads/leads/{id}/attribution`;
- `GET /api/ads/notifications`;
- `GET /api/ads/notifications/unread-count`;
- `POST /api/ads/notifications/{id}/read`.

## UI

Роль сохраняется после `/api/auth/telegram` или читается из `/api/auth/session`. Пункт «Реклама» и колокольчик отображаются только для `owner`. Прямые API-вызовы мастера всё равно блокируются backend.

Экран содержит агрегированную таблицу метрик, импорт, журнал, очередь ручной атрибуции и уведомления. Телефон не входит в TypeScript-типы и ответы API.

## Планировщик

Существующий scheduler получает рекламные задания:

- понедельник 09:15 — скан каталогов и импорт;
- 09:20 — напоминания по ручным площадкам;
- 09:30 — недельный дайджест и проверка алертов.

Напоминание создаётся не чаще одного раза за `reminder_period_days`. Дайджест содержит только агрегаты. При алерте создаются Markdown-черновики в `C:\D\Экодез\analysis\`; затем Telegram сообщает только, что черновик готов к одобрению. Функции отправки email отсутствуют.

## Приёмка

- миграция проходит на временной SQLite через batch alter, сохраняет строки и оставляет одну Alembic head;
- HMAC одинаков для одинакового телефона с одним ключом, отличается при другом ключе и нигде не сохраняет plaintext;
- импорт идемпотентен и журналирует успех/ошибку;
- UTM, phone match и manual проверены отдельно;
- CPL/ROMI рассчитаны на Decimal-фикстурах;
- owner-only проверен backend и frontend-тестами;
- напоминание не дублируется и не создаётся после свежего импорта;
- Telegram и уведомления не содержат телефон;
- агент создаёт только черновик и никогда не отправляет письмо;
- полный backend/frontend gate зелёный.
