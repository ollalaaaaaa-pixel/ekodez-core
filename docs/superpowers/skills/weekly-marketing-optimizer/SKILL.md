# Еженедельный оптимизатор ЭКОДЕЗ

## Входной шлюз

Если первых подтверждённых заявок ещё нет, B7 НЕ запускать. Вернуть «ожидание первых заявок». Отдельную диагностику формы/атрибуции можно предложить как другую задачу; не называть её выполненной еженедельной оптимизацией. Не создавать расписание автоматически.

## Отчёт по фактам

После первых заявок взять одинаковые семь дней по Москве и сопоставимый предыдущий период. Для каждого источника указать расходы рекламы, уникальные заявки Core, оплаченные связанные работы, полноту атрибуции и источники каждого числа. Дубли и тестовые заявки исключать только по подтверждённым признакам. Отсутствие данных — UNRESOLVED, не ноль.

| Показатель | Расчёт |
|---|---|
| CPL | рекламные расходы / уникальные подтверждённые заявки |
| ROAS | выручка связанных работ / рекламные расходы; отдельно указать окно оплат |
| ROMI | только при известной маржинальной прибыли и согласованном составе маркетинговых затрат |

При нуле заявок CPL=null. Клик по телефону или переход в бот не заявка. Выручка не прибыль. Разные даты расхода/создания заявки/оплаты показать, не смешивать когортную и календарную оценку. Малую выборку назвать малой, не объявлять канал победителем по трём заявкам.

## Последовательность решений

Сначала проверить учёт: работает ли источник, подтверждается ли отправка, нет ли повторного учёта платежей. Затем описать одну проверяемую гипотезу, изменение, стоимость, срок и критерий остановки. Бюджеты и прогнозы не брать из чата практиков.

Одобренная стратегия и срочность не разрешают менять расходы. До «запускай» и конкретного дневного лимита — только предложение. ВК меняется после «применяй». Публикации без имён/ников, чужих кейсов как собственных результатов и непроверенных правовых утверждений. Пометка для последних: ТРЕБУЕТ ПРОВЕРКИ.

Формат: Статус / Факты / Риски / Решения владельцу. Приложить таблицу периодов и каналов с арифметикой. Действия в кабинетах описывать только после проверяемого выполнения.

## Проверочный пример

Расход ВК 6000.00, 30 переходов в бот, ноль заявок → CPL=null; проверять воронку. Директ 3000.00, три заявки → CPL=1000.00; связанные оплаты 9000.00 дают ROAS=3.00, но не подтверждённый ROMI. Без дневных лимитов бюджет не переносить. Это синтетика, не результаты ЭКОДЕЗ.
