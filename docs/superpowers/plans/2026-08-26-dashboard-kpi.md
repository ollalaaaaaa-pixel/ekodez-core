# Этап 4 — Dashboard KPI и ручная привязка доходов к объектам

## Цель

Добавить единый дашборд за включительный период и ручную связь доходных финансовых операций с объектами. Автоматическое сопоставление по тексту операции или контрагенту не выполняется.

## Backend

1. Сначала добавить тесты, которые фиксируют:
   - nullable/indexed FK `transactions.object_id -> objects.id` и сохранность старых строк после SQLite-миграции;
   - выбор объекта при ручном доходе;
   - привязку и отвязку уже существующего импортированного дохода отдельным endpoint;
   - запрет привязки расхода и несуществующего объекта;
   - состав `/api/analytics/dashboard`, включительные границы дат и ошибку для обратного диапазона;
   - Decimal-расчёты и инвариант `linked_revenue + unassigned_revenue == revenue`;
   - `top_objects` только по привязанным доходам, `top_services` по категориям дохода, `best_day` по максимальной дневной выручке;
   - нулевые метрики для пустого периода.
2. Реализовать модель, миграцию, схемы и endpoints минимально до прохождения тестов.
3. Для заявок использовать когортную конверсию: `total_leads` — заявки с `order_at` (или `created_at`, если `order_at` отсутствует) в периоде; `closed_leads` — заявки этой когорты с текущим статусом `done`.
4. Денежные и процентные значения округлять через `Decimal` до двух знаков и отдавать строками по действующему API-контракту проекта.

## Frontend

1. Сначала добавить тесты для нового экрана Dashboard и привязки объекта в Finance.
2. Добавить Dashboard с периодом, KPI, дневным SVG-графиком выручки/прибыли, топом объектов и услуг. Подпись топа объектов: «по привязанным операциям». При пустом списке показать «Привяжите доходы к объектам в „Финансах“».
3. В ручной форме дохода на экране «День» добавить необязательный выбор объекта.
4. В таблице «Финансы» для каждой доходной операции добавить действие «Привязать объект» с возможностью изменить или снять связь. Список объектов загружать из существующего API.

## Проверка и выпуск

1. До миграции рабочей SQLite-БД сделать проверенную копию вне Git.
2. Выполнить backend: unittest, ruff, black --check, mypy.
3. Выполнить frontend: test, lint, build.
4. Проверить `/health`, `/health/db`, Dashboard и Finance в UI; сохранить скрин UI-приёмки вне Git.
5. Проверить diff и отсутствие секретов/БД, создать коммит `feat: dashboard KPI with object linking`, push в `main`, затем сверить remote SHA.
6. Этап 5 не начинать без команды владельца «далее».
