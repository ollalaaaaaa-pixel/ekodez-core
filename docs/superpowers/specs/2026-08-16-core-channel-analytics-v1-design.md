# CORE-CHANNEL-ANALYTICS-V1 — аналитика источников заказов

Статус: `REVIEW`

## Цель

Добавить к доходным операциям утверждённый канал привлечения и показать, какой
канал даёт больше денег, операций и средний чек за выбранный период.

## Каналы

Фиксированный список хранится в backend-коде и дословно повторяется во frontend:

1. Яндекс
2. 2ГИС
3. Авито
4. ВК
5. Сарафан
6. Прочее

`Прочее` выбирается для доходов вне каналов привлечения, включая юридических
лиц по счёту. Пустое значение остаётся допустимым и в аналитике отображается
отдельно как `Не указан`.

## Данные и миграция

В модель `Transaction` и таблицу `transactions` добавляется nullable-поле
`channel String(50)`. Внешний ключ и отдельная таблица каналов не создаются.
Существующие операции получают `null` и сохраняются без изменения остальных
полей.

`TransactionIn`, `TransactionOut` и `DayEntryIn` получают
`channel: str | None`. Backend принимает для дохода только значение из
утверждённого `CHANNELS` либо `null`; неизвестное значение получает HTTP 422.
Для расхода канал принудительно сохраняется как `null`.

На экране «День» форма дохода показывает необязательный Select из шести каналов.
Форма расхода канал не показывает. Telegram-черновики в этой версии сохраняют
`channel = null`; автоматическое распознавание канала не добавляется.

## API аналитики

`GET /api/analytics/channels?start_date=YYYY-MM-DD&end_date=YYYY-MM-DD` проверяет,
что начало периода не позже окончания; нарушение получает HTTP 422.

В расчёт входят операции, удовлетворяющие условиям:

- `kind == "income"`;
- `operation_date >= start_date`;
- `operation_date <= end_date`.

Дополнительный фильтр по `review_required` не применяется: это дословно следует
из утверждённого владельцем условия `только kind="income"`.

`channel = null`, пустая строка и строка из пробелов объединяются в группу
`Не указан`.

Для каждой группы рассчитываются:

- `total_amount` — сумма, округлённая до 2 знаков;
- `count` — количество доходных операций;
- `avg_check` — сумма, делённая на count, округление до 2 знаков;
- `share_percent` — процент от `period_total`, округление до 2 знаков.

Расчёты выполняются через `Decimal`. JSON сохраняет денежные значения и проценты
с двумя знаками как числовые значения FastAPI. Каналы сортируются по
`total_amount` убыванию, затем по названию для стабильного порядка. При отсутствии
операций возвращается `period_total = 0` и пустой список `channels`.

Формат ответа:

```json
{
  "period_total": 22000.00,
  "channels": [
    {
      "channel": "Авито",
      "total_amount": 12000.00,
      "count": 2,
      "avg_check": 6000.00,
      "share_percent": 54.55
    }
  ]
}
```

## Экран «Финансы»

Под существующими итоговыми карточками добавляется отдельный блок `По каналам`.
Существующая таблица операций сохраняется.

Быстрые периоды:

- `Неделя` — последние 7 календарных дней, включая сегодня;
- `Месяц` — от первого дня текущего месяца до сегодня;
- `3 месяца` — от первого дня месяца два месяца назад до сегодня;
- `Год` — от 1 января текущего года до сегодня.

По умолчанию выбран `Месяц`. Кастомный диапазон в версии 1 не добавляется.

Для каждого канала выводится карточка или строка:

- название;
- progress-bar с `share_percent`;
- сумма;
- количество заявок;
- средний чек.

Группа `Не указан` отображается наравне с каналами, чтобы показывать качество
заполнения. При пустом периоде выводится `Доходов за выбранный период нет`.
Ошибка API показывает уведомление и не стирает уже загруженный результат.

На ширине меньше 768 px каналы располагаются одной колонкой. Название и метрики
переносятся без горизонтальной прокрутки, цифры сохраняют денежное форматирование.

## Тестирование и живой сценарий

Backend-тесты покрывают:

- точный список `CHANNELS`;
- запись допустимого канала и отклонение неизвестного;
- принудительный `null` у расхода;
- четыре дохода в разных каналах с разными суммами;
- сумму, count, avg_check и share_percent;
- группу `Не указан`;
- включительные границы дат и исключение операций вне периода;
- сортировку и пустой результат.

Живой сценарий создаёт синтетические проведённые доходы текущего месяца:

- Авито — 5 000;
- Авито — 7 000;
- Сарафан — 10 000;
- `channel = null` — отдельная контрольная сумма.

Ожидание для Авито: count 2, total 12 000, avg 6 000. После API- и UI-проверки
синтетические операции удаляются разрешённым способом.

Frontend проходит lint и production build. Скриншоты фиксируют блок `По каналам`
на desktop и ширине меньше 768 px. `.env`, токены, вложения, `tg_offset.json` и
`backend/sample_order.txt` не входят в коммиты.
