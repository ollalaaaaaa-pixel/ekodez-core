# CORE-CHANNEL-ANALYTICS-V1 — аналитика источников заказов

Статус: `REVIEW`

## Цель

Добавить к доходным операциям источник заказа и показать владельцам выручку,
количество операций, средний чек и долю каждого канала за выбранный период.

## Выбранный подход

Используется динамический справочник каналов в PostgreSQL. Фиксированный список
без добавления новых каналов потребовал бы изменений кода, а свободный текст в
каждой операции создавал бы дубли и опечатки. Справочник сохраняет единые названия
и позволяет расширять список из интерфейса.

Стартовые каналы:

1. Авито
2. Яндекс
3. 2ГИС
4. Сарафан
5. Агрегатор
6. Постоянный клиент
7. Другое

## Данные и миграция

В `transactions` добавляется nullable-поле `channel String(100)`. Поле остаётся
строковым и без внешнего ключа: историческая операция продолжает отображаться,
даже если канал позже будет деактивирован.

Новая таблица `channels`:

- `id` — первичный ключ;
- `name` — `String(100)`, уникальное отображаемое название;
- `is_active` — активность, по умолчанию `true`;
- `created_at` — время создания на стороне БД.

Миграция создаёт таблицу, регистронезависимый уникальный индекс, добавляет семь
seed-записей и nullable-колонку `transactions.channel`. Существующие операции
получают `null` и в аналитике объединяются как `Не указан`.

## Ввод операций

`TransactionIn`, `TransactionOut` и `DayEntryIn` получают `channel: str | None`.
Для дохода экран «День» показывает Select активных каналов. Выбор необязателен:
это сохраняет возможность быстро внести доход и обеспечивает требуемую группу
`Не указан`. Для расхода поле канала не показывается и backend сохраняет `null`.

Новые API справочника:

- `GET /api/channels` — активные каналы по `id`;
- `POST /api/channels {name}` — создание после trim; пустое имя или длина больше
  100 символов получает 422, регистронезависимый дубликат получает 400.

На форме дохода доступна кнопка `＋ Новый канал`. После успешного POST новый канал
добавляется в Select и автоматически выбирается. Telegram-черновики в версии 1
не угадывают канал автоматически и сохраняют `null`, если источник не введён
владельцем.

## API аналитики

`GET /api/analytics/channels?start_date=YYYY-MM-DD&end_date=YYYY-MM-DD` проверяет,
что начало периода не позже окончания; нарушение получает HTTP 422.

В расчёт входят только проведённые операции:

- `kind == "income"`;
- `review_required == false`;
- `operation_date` включительно между `start_date` и `end_date`.

Черновики исключаются, чтобы неподтверждённые суммы не завышали выручку.

Для каждого канала рассчитываются:

- `total_amount` — сумма `Decimal`, 2 знака;
- `count` — количество доходных операций;
- `avg_check` — `total_amount / count`, `Decimal`, 2 знака;
- `share_percent` — доля от `period_total`, `Decimal`, 1 знак.

Пустые и whitespace-значения объединяются как `Не указан`. Результат сортируется
по `total_amount` убыванию, затем по имени канала для стабильности. При нулевой
выручке возвращается `period_total = 0` и пустой список каналов.

## Экран «День»

Сразу под итогом дня размещается компактная карточка `Источники за сегодня`.
Она использует тот же analytics API с датой начала и окончания, равной выбранной
дате. Карточка отображается только при наличии доходов с реальным каналом;
строка `Не указан` скрывается только в этом компактном блоке. Каждая строка:
название, сумма и количество операций.

## Экран «Финансы»

Добавляются вкладки `Операции` и `По каналам`. Существующая таблица остаётся во
вкладке `Операции` без изменения логики.

Вкладка `По каналам` содержит быстрые периоды:

- Неделя — последние 7 календарных дней, включая сегодня;
- Месяц — от первого дня текущего месяца до сегодня;
- 3 месяца — от первого дня месяца два месяца назад до сегодня;
- Год — от 1 января текущего года до сегодня;
- произвольный диапазон через `RangePicker`.

Для каждого канала выводится карточка: название, progress-bar доли, сумма,
количество заявок и средний чек. `Не указан` показывается здесь, чтобы владелец
видел качество заполнения данных. На ширине меньше 768 px карточки идут одной
колонкой, показатели переносятся без горизонтальной прокрутки.

## Ошибки и пустые состояния

Ошибка загрузки справочника или аналитики показывает уведомление и не стирает
уже загруженные данные. Пустой период показывает понятный текст `Доходов за
выбранный период нет`. Деление на ноль исключено.

## Проверка

Backend-тесты покрывают миграционную модель, справочник, границы дат, группу
`Не указан`, исключение расходов и черновиков, точные Decimal-агрегаты,
share-percent и сортировку.

Живой сценарий создаёт три проведённых дохода текущего месяца: Авито 5 000,
Авито 7 000, Сарафан 10 000. Ожидание для Авито: count 2, total 12 000,
avg 6 000. После скриншотов синтетические операции удаляются разрешённым способом.

Frontend проходит lint/build и визуальную проверку desktop/mobile вкладки
`По каналам`. `.env`, токены, вложения, `tg_offset.json` и
`backend/sample_order.txt` не входят в коммиты.
