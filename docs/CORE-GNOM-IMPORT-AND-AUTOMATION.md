# CORE-GNOM-IMPORT-AND-AUTOMATION

Реализация по команде владельца 15.09.2026 в feat/gnom-import от main f7e558d.

## Контур

Парсер определяет XLSX/CSV/HTML-XLS по содержимому и полному набору заголовков.
Каждый файл применяется одной транзакцией; сигнатура Start + phone_hash +
address_hash уникальна. Исправленная строка обновляет связанные записи.
Изменение Start означает новую сигнатуру; перенос маркируется, автоматического
слияния разных дат нет. При неоднозначности идентификации импорт отклоняется.

PII шифруется существующим Fernet-ключом; доменные HMAC для телефона и адреса
выводятся из него. Новых секретов/переменных окружения нет. Исходный Comments
хранится только внутри encrypted_pii лида. Строка «Вы напарник» исключена из
экстракторов. Participants и Created By не используются для реестра мастеров.

История — Lead + Object + Client + Treatment + связанная запись Gnom.
Доход создаётся сразу; расход хранится кандидатом и применяется владельцем.
Уникальность дохода по lead_id сохраняется частичным индексом kind=income;
это позволяет связать подтверждённый расход с той же заявкой.

Общие категории Core не переименовываются. Источники Gnom aggregator/yandex/phone
получают явные подписи; метрики агрегаторов публикуются под aggregators.

Новые заявки ищут историю по HMAC телефона или нормализованного адреса.
Подсказка цены — медиана завершённых исторических работ по вредителю, единице
площади и городу. Она не записывается в цену. Гарантийный срок хранится в
настройках импорта, изначально не задан; его определяет владелец.

Кандидаты препаратов/методов/условий требуют подтверждения владельца. Автозаписи
в боевой справочник нет. Ветка независима от ещё не слитого CORE-CHEM-DICT;
подтверждённый кандидат может ссылаться на существующую Inventory-позицию.

## Переходный период

Настройка weekly_enabled изначально false. Владелец включает её явным действием
в UI. После этого понедельник 09:10 (Москва): скан import/gnom, журнал результатов,
безопасное напоминание о выгрузке и секция недельной аналитики через owner-alert.
Действующий ежедневный job сохраняется. После merge ads перевод уведомлений
в общий центр выполняется отдельной задачей/коммитом.

Разовый исторический прогон выполняется только после «импортируй историю».
Сейчас разрешены реализация и синтетические проверки. Merge, рабочая миграция,
restart и публикация ожидают «применяй».
