# CORE-QUIZ-SMOKE-FIX

Единая конфигурация имени бота: `config/telegram.json`,
`BOT_USERNAME = @Ecodes29_Bot`. Сайт импортирует её для ссылок и кнопок.
В URL символ @ не используется: `https://t.me/Ecodes29_Bot?start=quiz_test`.

Поддерживается `quiz_<campaign>`: непустой campaign из A–Z, a–z, 0–9,
дефиса и подчёркивания, до 59 символов (весь Telegram start до 64 символов).
Список кампаний не фиксирован. Старые m_vk/m_avito/m_yandex_direct/m_seo/m_site
сохранены. Известная кампания сохраняет канал, произвольная получает other;
точная campaign хранится зашифрованной в черновике до его завершения.
Сайт передаёт только проверенный источник, не произвольные пользовательские
ответы, телефоны или UTM-поля. Новый прямой токен можно задать в диплинке.

При создании TelegramClientDraft владелец из OWNER_TG_ID получает немедленный
алерт с campaign. Адрес и вредитель ещё не переданы — выводится «ещё не указан».
После ОТПРАВИТЬ и создания лида приходит второй алерт с ID, campaign и полями
из описания: строки `Адрес: ...`, `Вредитель: ...` либо `Что нужно решить?: ...`.
Телефоны исключаются, в том числе вставленные в адрес, вредителя или campaign.
Уведомление выполняется после commit, независимо от утренней сводки.
Повтор одного update не создаёт дубль лида или алерта. При ошибке отправки
бот делает штатные три попытки; затем пишет обезличенную ошибку. Отдельной
очереди повторной доставки после исчерпания этих попыток нет.

Согласие клиента обязательно до сбора описания и контакта; чужие команды
владельца запрещены. Миграции не требуются, рабочие записи вручную не менять.

Живой смоук: владелец отправляет /today; пользователь вне allowlist открывает
quiz_test, нажимает Старт и проходит согласие. Для завершения заявки отправляет
описание с отметкой ТЕСТ и подтверждает ОТПРАВИТЬ. Проверить алерты владельца.
Удаление рабочих тестовых записей — только отдельным согласованным действием
по точным ID. Синтетические тесты используют временную SQLite, без Telegram.
Сайт и реклама остаются неопубликованными.
